# 屏幕操控路线图

目标：让 Solvhen 成为能真正替人操作手机的助手——不是"能点坐标"，而是"能做完整件事"。

## 参照对象

- **Mika**（wangzan101/Mika，Kotlin，设备端 agent）：以结构化界面理解 + 语义动作 + 多步执行为核心，Agent 直接操作 app 与网页。
- **DSHgo**（just-a-FA-for-name/DSHgo 等）：把 PC 侧工作台接到手机，强调"开包即用"的连接与远程可控性。

Solvhen 的差异点在于：**本地优先 + 用户自带 Key + 逐次确认的安全模型**。所以本路线图的做法是——借 Mika 的"看懂了再动手"，借 DSHgo 的"连得上就能用"，但所有副作用动作仍走 Solvhen 自己的策略引擎。

## 下一阶段

### P0 — 让它稳

1. **真机冒烟**：微信发消息、淘宝搜索、设置里改一项、返回链恢复——四条主链路各录一次完整序列。
2. **失败恢复**：动作失败时自动重读界面；连续两次相同失败就停下问人，不空转。
3. **元素定位兜底链**：id → viewId → text → 近似坐标（按屏幕比例）；每个失败都记录到审计，攒出常见应用的选择器库。
4. **序列事务化**：`device_act` 支持 `onFailure: abort|retry|skip` 与失败后自动截图，便于人看现场。

### P1 — 让它快

5. **界面差异增量**：只回传与上次 dump 的差异节点，长列表翻页时省掉大量上下文。
6. **动作合并**：相邻的 tap+input+wait 合成一次原生调用，减少 MethodChannel 往返。
7. **应用知识包**：把高频应用（微信、支付宝、淘宝、地图）的常用路径写成可复用技能，Agent 直接调用而不必每次摸索。

### P2 — 让它全能

8. **视觉兜底**：UI 树为空（游戏、Flutter 自绘、部分 WebView）时走截图 + 视觉模型定位，结果回填成一次临时节点。
9. **多应用流程**：跨应用任务（从聊天里拿到地址 → 打开地图导航）需要一个轻量的"任务上下文"来记住跨应用中间状态。
10. **远程可达（借 DSHgo 思路）**：手机作为执行端、PC 作为模型/算力端的安全隧道；与现有 OneBot 桥接复用同一套来源隔离。
11. **计划-执行-复核三段式**：复杂任务先出计划让人确认一次，执行中只在关键节点回报，结束后给出可回看的操作录像（帧序列 + 动作日志）。

### P3 — 让它可信

12. **操作回放**：把一次 run 的动作与界面快照存成本地可回看的 trace，出问题能定位到第几步。
13. **敏感界面护栏**：识别支付、密码、验证码、授权页时强制逐次确认并默认拒绝自动填写。
14. **能力分级**：用户可按应用授予"只读观察 / 可点击 / 可输入 / 全自动"，而不是全局一刀切。

## 刻意不做

- 不做免确认的静默批处理：`device_act` 始终逐次确认。
- 不做需要 root 的注入方案：全部走官方无障碍 API。
- 不把"允许"类权限弹窗纳入默认清理范围。
- 不承诺"任意应用可用"：无障碍树读不到的内容必须走截图兜底，且要如实标注不确定性。
